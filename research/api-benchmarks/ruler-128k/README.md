# RULER 128K

How well a model uses a long context: 13 synthetic tasks (needle retrieval, variable tracing, word aggregation, QA
over many documents) at input lengths from 4096 to 131072 tokens, scored by string match, without a judge model.
The measurement plan, fixed before the first output, is [PROTOCOL.md](PROTOCOL.md) with its amendments. Refs #306.

- Paper: [Hsieh et al. 2024, RULER: What's the Real Context Size of Your Long-Context Language Models?](https://arxiv.org/abs/2404.06654)
- Harness: [NVIDIA/RULER](https://github.com/NVIDIA/RULER) @ `db43f92ff634bbce1c33d1fb15858aec4bba509a`: data from
  `scripts/data/prepare.py` (base template), scoring with `scripts/eval/evaluate.py` (`string_match_all` for the
  `niah_*`, `vt`, `cwe`, `fwe` tasks, `string_match_part` for `qa_1`, `qa_2`)
- Data: generated by RULER for each model with its own tokenizer, seed 20261122, 50 samples per task and length.
  Sources, as RULER's own download scripts fetch them: Paul Graham essays (`download_paulgraham_essay.py`), SQuAD
  v2.0 dev and HotpotQA dev (`download_qa_dataset.sh`), `english_words.json` (RULER's git-lfs file, checked against
  its oid). The sha256 of each source file is in the `data` field of every result.
- Metric: mean of the 13 task scores at 131072 tokens (percent); stderr from a bootstrap over samples within tasks
  (10 000 resamples). Each result file also has the mean per length, each task per length and the four categories
  (retrieval: the 8 `niah_*`; tracing: `vt`; aggregation: `cwe`, `fwe`; QA: `qa_1`, `qa_2`) in `other_metrics`.
- Settings: RULER's input and answer prefix as one user message through the model's chat template with its
  defaults, temperature 0.6, top_p 0.95, seed 20261122 per request, output up to the context window minus the
  input; the text after the last `</think>` is scored. LFM3-1.7B on vLLM 0.34.0, bf16, which also applies `top_k` 50
  and `repetition_penalty` 1.1 from the model's `generation_config.json` (PROTOCOL.md, Amendment 3); Bielik 11B v3.1
  through the Fabryka AI API. Slayer: RULER's raw prompt, greedy, RULER's per-task answer budget (30 to 128 tokens),
  4096 only. Every result has the sampling in effect in `settings.sampling` (sent fields, what the server filled in;
  for the API its defaults are unknown) and in `provenance` the commit of this repo with a dirty flag, the sha256 of
  the runner files and the GPU and platform of each generating `run.sh` call and of the summary.
- Extra services: the Fabryka AI API (`https://fabryka.ai/v1/chat/completions`) for Bielik

## Hypotheses

`python3 compare.py` (from this directory, after the runs) reads `results/<model-id>.json` and `.jsonl.gz` and
evaluates PROTOCOL.md as amended: the control first (LFM3-1.7B at 131072 against its card value 65.56), then R1
and R3 for LFM3-1.7B and R2 for LFM3-1.7B against Bielik 11B v3.1 over the lengths both models measured (Slayer per
length, descriptive only). It prints the control as measured (z and PASS or FAIL against 65.56) with its status
`not comparable (Amendment 4)`, every `deviation:` from the protocol's wording, the lengths and error rows left
out, a table per hypothesis (value with bootstrap SE, z, Holm-adjusted p over all three hypotheses, verdict,
outcome, n, and the same under strict scoring next to it) and the per-length means under both scorings, and writes
the same to `results/hypotheses.json`. A hypothesis whose model has not run is `not run` and still counts in the
Holm family (m = 3). The bootstraps are independent per model (Amendment 1).

## Deviations

- **50 samples per task and length, not RULER's 500.** A cost decision taken before the run (PROTOCOL.md): 650
  samples per length. The task scores have a wider stderr than in the paper.
- **Bielik through the Fabryka AI API, with its hidden provider system prompt** (Amendment 1, #277). The API applies
  Bielik's chat template with its defaults, which add a provider system prompt in Polish with the current date; it
  rejects `chat_template_kwargs`, so the prompt cannot be turned off or the date pinned. Requests carry only
  `model`, `messages` (plain string content), `max_tokens`, `temperature`, `top_p` and `seed`, the fields the API
  accepted in [ifeval](../ifeval/README.md) (it rejects `"type": "text"` parts and `"stop": []`). 2 requests at a
  time; after any failed request all requests pause (10 s, doubling up to 5 minutes), up to 30 retries per
  request, as in ifeval.
- **Bielik's prompt length is counted locally, with a 256-token margin.** The API has no `/tokenize`.
  `predict.py` counts each templated prompt with Bielik's own tokenizer and chat template at the pinned revision,
  template defaults included (a one-sentence message counts 1057 tokens here; ifeval saw about 1065 billed). The
  fit check is counted prompt + 256 + RULER's answer budget <= 32768, and `max_tokens` is 32768 - counted prompt -
  256. The margin covers differences the local count cannot see (the API's template version and date line).
  Each raw record keeps the API's own `prompt_tokens` next to the local count, and `predict.py` prints the largest
  difference after each length. With the system prompt, RULER's 32768-token samples are not expected to fit, so
  Bielik's 32768 is expected to be `null` and R2 to use 4096-16384.
- **Output limit: the context window minus the templated input.** RULER caps the answer at 30 to 128 tokens. The
  instruction-tuned models here may reason before they answer, so they get the rest of the window (PROTOCOL.md). A
  response that hits the limit is still scored (with no `</think>` the whole text is scored, as in IFEval); their
  number per length is `other_metrics.unfinished`.
- **RULER's input with its answer prefix as one user message.** The way RULER's own OpenAI client sends it
  (`call_api.py`, `client_wrappers.OpenAIClient`). The scorer is a case-insensitive substring match on the
  references, so the answer format does not change the score.
- **A length is measured only when every templated prompt fits.** RULER counts `max_seq_length` without the chat
  template. Before generating, `predict.py` counts each prompt with the chat template (vLLM's `/tokenize`, or
  locally for the API); if one of them plus RULER's answer budget exceeds the window, the whole length is `null`
  with the reason, not cut down.
- **A task RULER cannot generate at a length is skipped there, not scored 0.** RULER's QA generator
  (`scripts/data/synthetic/qa.py` L196-206 @ db43f92) loops forever when even its smallest set of documents (10)
  exceeds the length with the model's tokenizer. `run.sh` runs each `prepare.py` call under a wall-clock limit
  (`PREPARE_TIMEOUT`, default 1200 s) and, when it is hit, writes `data/<task>/skip.json` with the reason. That task
  is `null` at that length; the length mean is over the remaining tasks and flagged `partial: true` with the skipped
  tasks. A partial length is not comparable: the headline, the control and R1 need all 13 tasks at 131072 and are
  `null` / `not run` there, and R2 and R3 use only lengths complete for the compared models.
- **Sampling settings the protocol did not name, from LFM3-1.7B's `generation_config.json`** (PROTOCOL.md,
  Amendment 3). vLLM 0.34.0 fills what the request does not set from the model's generation config: `top_k` 50 and
  `repetition_penalty` 1.1, as in the [ifeval](../ifeval/README.md) LFM3 run. The protocol names only temperature,
  top_p and the seed; this was found by the LiveCodeBench verification after the LFM3 run had started and before
  any LFM3-1.7B RULER result was summarized. The values are recorded in `settings.sampling`; their effect on the
  score is not estimated (an ablation is a separate decision).
- **Provenance and input checks added while the first runs were going.** `run.sh` now writes
  `out/<model-id>/generation.jsonl` (commit and dirty flag, runner sha256, GPU and platform, effective sampling) before
  generating and `inputs.sha256.json` after scoring; `summarize.py` stops when an input differs from it, and
  `compare.py` when a result file differs from `results/results.sha256.json`. The LFM3-1.7B run (started from
  d45c3509) and the Slayer run (920787d4) predate this: their results have `provenance.generation: null` with the
  reason, the sampling read from the pinned `generation_config.json` at summary time, and the input sha256 taken at
  their first summary, not when the files were written; each gap is a line in the result's `warnings`.
- **The control is `not comparable`, and every score is also given under strict scoring** (PROTOCOL.md, Amendment
  4, decided after the result and after the control failed). Measured, LFM3-1.7B at 131072 is 71.69 +- 0.93
  against the card's 65.56 (z = 6.62, FAIL); that stays reported. The card states no RULER setup (harness, thinking
  mode, samples, scoring of unfinished reasoning, output cap; card @ `1da06bec` line 536 gives only serving and
  sampling defaults), so its value is no pass/fail target, and R1-R3 are read with the control marked
  `not comparable`. Liquid was not asked. Strict scoring: an output without `</think>` scores 0 (at 131072, 10 outputs
  loop to the length limit without it and 8 of them score above 0 on their whole text); LFM3-1.7B strict at 131072
  is 70.51. Results carry it in `strict` (headline) and `other_metrics.strict` (per length, task and category, with
  the count of outputs without `</think>`), the `.jsonl.gz` rows in `closed_think`. Verdicts stay on the
  pre-registered scoring, the strict verdict is shown next to each. Slayer (raw prompt, no reasoning block) has
  only the pre-registered score.
- **Strict scoring applies only where the generation prompt opens a reasoning block** (PROTOCOL.md, Amendment 5,
  correcting Amendment 4's parenthesis). LFM3-1.7B's template ends the generation prompt with an open `<think>`, so
  an output without `</think>` never left its reasoning. Bielik's template ends it `<think></think>` (reasoning
  closed by the template), so its outputs never carry `</think>` and strict scoring would make every sample 0; it
  is null with the reason, as for Slayer's raw prompt. `run.sh` records the rendered prompt end in
  `generation.jsonl` (`reasoning`); for an out dir without it, `summarize.py` renders one prompt with the pinned
  chat template, its defaults and the generation prompt. Results carry it in `other_metrics.strict.reasoning`.
- **API failures logged per attempt, not for the first Bielik run.** `predict.py` writes every failed attempt,
  pause and recovery to `out/<model-id>/<length>/api-events.jsonl` (UTC time, task, sample, endpoint, attempt, HTTP
  status, the first 300 characters of the error, action, pause in seconds), as `../livecodebench-v6` does; the
  counts go into the `generation.jsonl` line of each `run.sh` call and into `provenance.api_events` of the result,
  and the files' sha256 are checked with the other inputs. A body cut short of its Content-Length
  (`IncompleteRead`) and a reset connection are retried like a 5xx. The Bielik run of 2026-11-22 predates the log:
  its result has `api_events: null`, with the reason given to `summarize.py --no-event-log-reason`: its console log
  shows 7 x HTTP 503 "bielik-11b-v3.1 is temporarily unavailable", all recovered on attempt 2, with no timestamps.
- **Tokenizer library.** RULER pins transformers 4.44.2; LFM3-1.7B's tokenizer (`TokenizersBackend`) needs
  transformers 5.x, so data generation, prompt counting and serving use transformers 5.22.2 for every model
  (`requirements.lock.txt`). The token counts come from the same tokenizer files.
- **Scoring without NeMo.** `evaluate.py` imports the NeMo toolkit only for `read_manifest` (read a JSON-lines
  file); `nemo_shim/` provides that function, so RULER's evaluator runs unchanged without NeMo. `summarize.py`
  scores each sample with RULER's own `postprocess_pred` and metric function, for the bootstrap and the
  `.jsonl.gz`, and stops if their per-task means differ from `evaluate.py`'s scores.
- **Slayer is a training checkpoint, converted** (Amendment 2). `run.sh` downloads `wagi_70000.pt` (checked against
  its sha256 by `research/tools/konwertuj.py`), converts it against `SlayerLab/Slayer1B-1.08` @ `5f854a0c` as
  `research/tools/przebieg_centralny.sh` does, and stops unless the converted `model.safetensors` has the sha256
  of the full run (`b9e31fc9…`). The converted directory is cached in `.cache/slayer1b-1.09-k70000/`.
- **Slayer's tokenizer for data generation.** Slayer's `config.json` has no `model_type`, so `AutoTokenizer`
  cannot load the converted directory; `run.sh` gives RULER a directory with only its `tokenizer.json` as
  `PreTrainedTokenizerFast` (the class `slayer_lm.py` uses). With BOS, every RULER sample at 4096 needs at most 4096
  positions, because the last generated token is never fed back; `slayer_predict.py` checks this per sample.
- **Essays are fetched live.** RULER's essay script downloads from paulgraham.com and GitHub at run time, so the
  haystack text is not pinned by RULER; compare the sha256 in the `data` field before comparing models.

## Errors

A request that fails after the retries (`predict.py`: transport errors, including a reset connection or a body cut
short, and HTTP 408/429/5xx; 8 retries on vLLM, 30 on the API) is recorded as an error and left out of the score;
it is never a zero. Other HTTP errors (e.g. 400) are recorded at once. Errors per task and length are in
`other_metrics.errors`; every failed attempt, pause and recovery is in `<length>/api-events.jsonl`, counted in
`provenance.api_events`; rerunning `run.sh` sends only the failed samples again. A published result has no errors.

## Reproduce

LFM3-1.7B and Slayer on a Linux machine with an NVIDIA GPU (H100 80 GB), python3, curl and git:

```bash
bash run.sh lfm3-1.7b --limit 5    # smoke test: 5 samples per task at 4096, written to out/, not results/
bash run.sh lfm3-1.7b
bash run.sh slayer1b-1.09-k70000
```

Bielik on any Mac or Linux machine, no GPU. It needs the API key and a Hugging Face login with access to the
gated `speakleash/Bielik-11B-v3.1-Instruct` (for its tokenizer and chat template; `run.sh` stops with the command
to run if the login is missing):

```bash
export FABRYKA_API_KEY=...
bash run.sh bielik-11b-v3.1 --limit 2    # smoke test
bash run.sh bielik-11b-v3.1
```

`CONCURRENCY` sets the parallel requests (default 32 on vLLM, 2 on the API), `PORT` vLLM's port. Everything
generated stays in `out/<model-id>/<length>/`: `data/` (RULER samples), `raw/` (every attempt, with reasoning),
`pred/` (RULER's prediction files and `summary.csv`), `skip.json` for a length that is not measured; and in
`out/<model-id>/`: `run.json`, `generation.jsonl` (one line per generating `run.sh` call) and `inputs.sha256.json`.
The run resumes where it stopped. The `date` in a result is the day the run first started.

Prompt tokens per model (50 samples x 13 tasks, about the length each): 2.7M at 4096, 5.3M at 8192, 10.6M at
16384, 21.3M at 32768, 42.6M at 65536, 85.2M at 131072; about 168M for LFM3-1.7B, about 19M for Bielik over
4096-16384 plus about 2.1M of its system prompt (1 057 tokens x 1 950 requests), 2.7M for Slayer. Output tokens
depend on how long each model reasons.
