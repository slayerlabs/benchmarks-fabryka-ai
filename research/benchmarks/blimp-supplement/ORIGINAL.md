| Format zadania | Para minimalna, wymuszony wybór między dwoma pełnymi tekstami, 0-shot. Model ocenia każdy tekst osobno. W `qa_congruence_*` tekst to pytanie i odpowiedź w dwóch liniach (`"What did you get?\nI got a chair."`), w `turn_taking` dialog dwóch osób w dwóch liniach z imionami (`"David: Should you quit?\nSarah: No, I shouldn't."`). Różnica leży raz w odpowiedzi (QA), raz w pytaniu (`turn_taking`), więc część wspólna nie zawsze jest prefiksem. |
| Prompt | Praca nie ma promptu: modele dają każdemu tekstowi log-prawdopodobieństwo (dla modeli maskowanych pseudo-log-prawdopodobieństwo). Kod autorów (`_template_yaml`): `doc_to_text: ""`, `doc_to_choice: "{{[sentence_good, sentence_bad]}}"`, `doc_to_target: 0`, `num_fewshot: 0`, domyślny `target_delimiter` `" "` (`lm_eval/api/task.py` forka). Oceniany tekst jednej opcji: `" " + sentence_good`, np. `" If she has a dog, it must be the case that she has a mammal."`. Przy pustym kontekście fork warunkuje na jednym tokenie `prefix_token_id` (BOS, gdy go nie ma: EOS, potem PAD; `lm_eval/api/model.py` i `models/huggingface.py`). Model `hf-mlm` liczy pseudo-log-prawdopodobieństwo przez `minicons` (Salazar i in. 2020). |
| Ocena | `acc`: para trafiona, gdy suma log-prawdopodobieństw tokenów `" " + sentence_good` jest większa niż dla `" " + sentence_bad`. Bez normalizacji długości i bez normalizacji tekstu (nic nie jest generowane). Remis: argmax wybiera pierwszą opcję, czyli zdanie poprawne, więc remis liczy się jako trafienie. Na zgłoszeniach konkursowych liczono te same pary z pliku predykcji (`score_predictions.py`); predykcją był tekst o najwyższym prawdopodobieństwie. |
